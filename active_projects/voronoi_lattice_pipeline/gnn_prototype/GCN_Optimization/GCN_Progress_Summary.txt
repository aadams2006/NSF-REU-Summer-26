Phase 1: Initial optimizer comparison
-------------------------------------
Source:
- active_projects/voronoi_lattice_pipeline/gnn_prototype/outputs/optimization/run_20260622_132717/optimizer_comparison.csv

What was tested:
- AdamW
- SGD + momentum
- SGD + Nesterov

Issue discovered:
- This comparison changed more than just the optimizer.
- It also changed hidden_dim, regularization, schedule behavior, clipping, and early stopping behavior.

Outcome:
- All tested optimizers performed much worse than baseline.
- Conclusion: the first comparison was not a clean optimizer-only test.


Phase 2: Fair optimizer comparison
----------------------------------
Source:
- active_projects/voronoi_lattice_pipeline/gnn_prototype/outputs/optimization/run_20260622_140527/optimizer_comparison.csv

What changed:
- Restored hidden_dim=24
- Restored weight_decay=1e-5
- Added Adam control run
- Matched Adam and AdamW to the same two-phase schedule
- Gave SGD variants longer runs and patience

Results:
- Adam control reproduced baseline almost exactly
- AdamW still underperformed badly
- SGD + momentum and SGD + Nesterov remained far below baseline

Key metrics:
- Adam control test R2: 0.9148
- AdamW test R2: 0.5101
- Best SGD test R2: 0.1424

Conclusion:
- The training pipeline was correct.
- Optimizer choice was not the main bottleneck.
- Plain Adam remained the best training method among the tested optimizers.

Phase 4: Richer node features from existing datasets
----------------------------------------------------
Code change:
- active_projects/voronoi_lattice_pipeline/gnn_prototype/colab_gnn_stiffness_prototype.py

What changed:
- No new lattice sets were required.
- Node features are now derived at load time from the existing node coordinates and adjacency matrix.
- The model still reads the same dataset files, but each node now includes:
  - x, y
  - node degree
  - weighted degree
  - distance from specimen center
  - boundary indicator
  - mean incident edge length
  - max incident edge length
  - mean incident edge weight

Purpose:
- Increase the amount of local geometric and connectivity information available to the GCN without regenerating data.
- Shift the next round of improvement toward representation learning rather than optimizer tuning.

Latest richer-feature single-run result:
- active_projects/voronoi_lattice_pipeline/gnn_prototype/outputs/richer_features/run_20260624_130608/metrics_summary.csv

- Test R2 improved from 0.9148 to 0.9403
- Test RMSE improved from 0.003818 to 0.003197
- Test MAE improved from 0.003003 to 0.002448

Interpretation:
- Richer node features produced a meaningful improvement.
- This is the strongest result so far.
- The previous ceiling was not absolute; it was largely a representation ceiling.
- The next requirement is robustness validation across multiple seeds rather than more optimizer work.

Phase 6: Graph-level summary feature integration
------------------------------------------------
Code changes:
- active_projects/voronoi_lattice_pipeline/gnn_prototype/colab_gnn_stiffness_prototype.py
- active_projects/voronoi_lattice_pipeline/gnn_prototype/GCN_Cloud_Notebook_Richer_Features.ipynb
- active_projects/voronoi_lattice_pipeline/gnn_prototype/GCN_Cloud_Notebook_Richer_Features_Multi_Seed.ipynb

What changed:
- Added graph-level summary features derived from the existing lattice files at load time.
- No new lattice sets were required.
- Each graph now includes summary features such as:
  - node count
  - edge count
  - graph density
  - total / mean / std edge weight
  - degree mean / std
  - weighted degree mean / std
  - center-distance mean / std
- The model now concatenates graph-level features after graph pooling before the output layer.
- Node features and graph-level features are both normalized using training-split statistics.

Purpose:
- Improve graph-level reasoning and reduce the remaining robustness gap on the prediction set.
- Build on the richer node-feature improvement without changing the underlying dataset files.

- Further optimizer, local architecture, and loss sweeps are unlikely to break the current ceiling without new information or a better understanding of the remaining error distribution.


Current assessment
------------------
1. The strongest confirmed training setup is still plain Adam with the two-phase schedule.
2. AdamW is consistently worse than Adam on this problem, even when matched fairly.
3. SGD + momentum and SGD + Nesterov are not competitive for this task under the tested budgets.
4. Weighted edges are worth keeping because they preserve real graph information and improved prediction-set behavior.
5. Richer node features remain a strong baseline for prediction-set behavior, but are no longer the top prediction-set result overall.
6. The current mean held-out test ceiling is shared by plain GCN-3 and the five-member GCN-3 ensemble:
   - richer graph features
   - target normalization
   - 3-layer GCN
   - Plain GCN-3 mean test R2: 0.945625
   - Ensemble mean test R2: 0.945631
   - The difference is negligible and should not be treated as an accuracy breakthrough.
7. There is now a measurable tradeoff between in-distribution accuracy and prediction-set generalization:
   - Best mean test R2: richer graph features + target normalization + 3-layer GCN
   - Best mean prediction-set R2: richer graph features + target normalization + residual 3-layer GCN
8. The 3-layer GCN is now modestly favored over the 2-layer control for in-distribution performance.
9. The benefit from greater depth is real but small, and does not materially improve prediction-set robustness.
10. Broad architecture-family swaps remain de-prioritized after GIN and GraphSAGE underperformed.
11. The original residual GCN-3 remains the strongest raw prediction-set model tested so far, but not the strongest mean test-accuracy model.
12. The narrow-LR residual GCN-3 is now the strongest stabilized residual variant and the best compromise residual candidate.
13. The residual GCN-3 line still looks more like a robustness/objective problem than a capacity problem.
14. The first broad residual retune was too aggressive and hurt prediction-set performance without improving test performance.
15. The narrow LR-only retune improved residual stability and mean test accuracy, but still did not beat the plain GCN-3 test baseline.
16. The first Huber-loss residual run was encouraging in that it crossed 0.95 test R2, but it was still worse than both plain GCN-3 and the best residual seed-42 baselines.
17. The Huber multi-seed validation showed modest worst-seed stabilization relative to the original residual line, but it still underperformed the narrow-LR residual retune and plain GCN-3 overall.
18. The fixed-split plain GCN-3 ensemble is now the strongest held-out test result overall, with test R2 = 0.9555.
19. However, that ensemble result is a fixed-split benchmark and should not be conflated with the earlier multi-split mean comparisons.
20. Further progress is now more likely to come from evaluation strategy, data-distribution analysis, or inference-level aggregation than from additional optimizer or loss-function sweeps.
21. Multi-split validation confirms that ensembling reduces test R2 variability by approximately 20 percent.
22. The ensemble improves the worst tested split from test R2 = 0.9343 to 0.9382.
23. The ensemble modestly improves mean prediction-set R2 from 0.4453 to 0.4578.
24. The cross-split ensemble mean test R2 is 0.9456, so the fixed-split 0.9555 result should not be reported as the expected general performance level.
25. The ensemble is now the preferred high-reliability configuration, while a single plain GCN-3 remains the preferred compute-efficient configuration.

- The best SGD result is still dramatically worse than baseline.

- AdamW as the primary replacement for Adam

Reason:
- AdamW is better than SGD here, but still substantially worse than Adam.
- It can remain as a low-priority sanity check after future representation changes, but it should not be the main focus now.

- Adam with the baseline two-phase schedule

Secondary method to keep only as a limited comparison:
- AdamW with the same schedule

Reason:
- Adam is the only method that consistently matches top performance.
- AdamW may still be worth re-checking after larger modeling changes, but not as the central direction.
